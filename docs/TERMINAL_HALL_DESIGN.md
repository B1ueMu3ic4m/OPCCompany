# 终端大厅设计

最后更新：2026-05-07

当前状态：终端大厅已达到单人本地正式使用基线。默认界面采用摘要工作台 + 员工终端卡片，不再把完整后台命令、路径、原始 transcript 或折叠式说明堆在首屏。

## 目标

终端大厅让老板同时看到所有 AI 员工干活，而不是只看一个员工的日志。它是 2D 公司场景之外的第二个核心工作界面。

## 界面结构

```text
┌─────────────────────────────────────────────────────────┐
│ 终端大厅                  [本地维护] [运行全部] │
├────────────────────┬────────────────────┬────────────────┤
│ Codex 技术负责人      │ Gemini 界面设计师      │ Claude Code     │
│ 状态：思考中         │ 状态：设计中          │ 状态：编码中      │
│ 运行前预检摘要       │ 运行前预检摘要        │ 运行前预检摘要    │
│ 中文任务摘要/状态     │ 中文任务摘要/状态      │ 中文任务摘要/状态  │
├────────────────────┼────────────────────┼────────────────┤
│ Codex 审查员         │ 测试工程师            │ 系统日志          │
│ 状态：待审查          │ 状态：待命            │ 事件/错误/审批     │
└────────────────────┴────────────────────┴────────────────┘
```

## 操作

- 每个员工一个终端卡片。
- 卡片显示状态、来源摘要、会话续跑摘要、运行前预检、任务摘要、退出码和交互状态。
- 老板可以点某个卡片放大。
- 可以给单个员工运行任务、写入预检审计、清空可见日志。
- 可以进入本地维护详情做真实终端工作区、手动交互轮次、自动交互循环、历史索引、归档迁移和维护巡检。
- 「运行全部」仍保留，但默认汇报提示词 + 多名可运行员工时必须先确认，避免误消耗多名员工额度。

## 技术路线

### 阶段 A：App 内多终端日志墙（已实现）

- 继续使用 `Process`。
- 每个员工独立 `terminalLogs[agentID]`。
- 新增 TerminalHallView。
- 支持多员工同时运行非交互 CLI。
- stdout/stderr 使用 Pipe 流式追加到对应员工终端。

当前 App 已支持：

- 主界面在“公司场景”和“终端大厅”之间切换。
- 每个非老板员工独立终端卡片。
- 单独运行、运行全部、选中员工、清空单个员工日志。
- Codex / Claude / Gemini 命令预览和输出记录。
- CLI 运行中会持续把 stdout/stderr 追加到员工终端卡片。
- 每个员工独立运行状态，运行完成后自动同步 CTO。

### 阶段 B：可控交互式会话

状态：已实现基础能力。

- 每个 AgentSession 记录：
  - process
  - stdin pipe
  - stdout buffer
  - stderr buffer
  - status
  - startedAt
  - exitCode

### 阶段 C：tmux 真实工作区

状态：已实现并接入本地维护区。

- 创建 `opc-company` tmux session。
- 每个员工一个 pane/window。
- App 通过 `tmux send-keys` 派任务。
- App 通过 `tmux capture-pane` 抓取展示。
- 老板可点“打开真实终端”进入 tmux。

当前真实终端实现补充：

- 完整任务通过一次性 runner 脚本发送，真实 pane 只接收短命令，避免长 prompt 触发 shell/file-name 竞态。
- 单行手动输入走字面量粘贴路径，不写作业档案，不影响完整任务 marker。
- 自动交互循环只在技术负责人维护区显式启动，且绑定任务上下文和最大轮次。

## 安全规则

- 代码类员工默认需要工作区权限。
- 危险命令需要老板批准。
- 并行改代码时必须使用 git worktree。
- CTO 可以查看所有终端摘要。
- 默认可见卡片不展示绝对路径、底层 CLI 参数或完整模型 transcript；完整材料保留在作业档案和维护日志。
