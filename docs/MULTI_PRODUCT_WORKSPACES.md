# 多产品工作区设计

最后更新：2026-05-07

当前状态：多产品工作区已经进入正式使用基线。产品切换、当前产品团队、产品级任务/消息/记忆/终端日志过滤、旧任务归属迁移和产品隔离体检已落地；本文保留模型设计和后续演进边界。

## 核心原则

OPC 公司不应该只有一个项目。正确结构是：

```text
OPC 公司
├── 产品工作区 A
│   ├── 独立仓库/目录
│   ├── 独立任务板
│   ├── 独立终端日志
│   ├── 独立文档和决策记录
│   └── 可绑定一组 Agent 员工
├── 产品工作区 B
└── 产品工作区 C
```

## 产品和员工的关系

- CTO 是公司级角色，可以看到所有产品。
- UI、工程、测试、审查员工可以被分配到一个或多个产品。
- 每个产品有自己的当前阶段：调研、设计、实现、测试、发布、维护。
- 每个产品有自己的根目录、Git 分支、环境变量和 CLI 工作目录。

## 数据模型

当前核心模型已经具备：

- `ProductWorkspace`
  - id
  - name
  - shortName
  - rootDirectory
  - status
  - stage
  - assignedAgentIDs
  - createdAt
  - updatedAt
- `ProductTask`
  - productID
  - ownerID
  - status
  - successCriteria
- `ProductTerminalSession`
  - productID
  - agentID
  - command
  - output
  - exitCode

仍按实际使用评估的后续项：

- 图形化 git worktree 管理器。
- 多产品磁盘占用/归档策略面板。
- 跨产品资源配额和员工排班冲突提示。

## UI 改造

左侧应该从“员工列表”升级为两层：

1. 产品切换器
   - 当前产品
   - 新增产品
   - 暂停/归档产品
2. 当前产品下的员工和任务

中间主界面随产品切换：

- 公司总览：所有产品进度
- 单产品办公室：当前产品团队工作区
- 终端大厅：按产品过滤员工终端

右侧面板随选择对象变化：

- 选中产品：产品总控台
- 选中老板：公司总控台
- 选中 CTO：跨产品调度台
- 选中员工：员工沟通/档案/终端

## 并行开发规则

- 每个产品默认独立 Git worktree 或独立目录。
- 同一名工程 Agent 同时只能写一个产品，避免上下文污染。
- CTO 可以跨产品查看状态，但派任务时必须指定产品。
- 终端命令必须以产品根目录作为 working directory。
- 每个产品的记忆、日志、任务、验收结论都独立保存。
