# 通信网关安全说明

最后更新：2026-05-07

当前状态：通信网关移动端联动和外部入站 HTTP 服务**不是**当前单人本地正式使用阻塞项。App 内本地指挥台、出站汇报规则、签名校验基础件和动作白名单逻辑保留；外部入站继续默认关闭，等用户真实需要远程或手机联动时再进入产品化评估。

## 当前边界

OPC 通信网关分为三层：

- 本地指挥台：用于在 App 内模拟手机指令，默认启用，可验证完整产品链路。
- 出站汇报：由老板或技术负责人在 App 内触发，发送到已配置就绪的飞书、企业微信、钉钉、Telegram 或邮件通道。
- 外部入站：后续 HTTP 服务入口，默认关闭；必须经过签名、时间戳、nonce 和动作白名单后才能进入 OPC。

手机指令不会直接执行命令、不会修改文件、不会跳过审批。它只会写入通信日志、通知当前产品团队负责人，并创建可追踪任务。

## 出站规则

- 通道必须启用并允许汇报。
- 外部通道必须配置完整地址；Telegram 还必须配置聊天标识。
- 发送失败时只记录脱敏后的主机级地址，不记录 webhook token、路径密钥或查询参数。
- LOCAL 通道不发网络请求，只记录本地成功。

## 入站签名规则

外部入站服务接入前必须使用：

- HMAC-SHA256 签名。
- ISO8601 时间戳，默认允许 5 分钟偏差。
- nonce 防重放，最近 1000 个 nonce 不可重复。
- 签名载荷：`timestamp.nonce.body`。
- 签名通过即视为该 nonce 已被消耗。即使后续 JSON 解析失败、动作不在白名单或字段缺失，也必须重新生成 timestamp、nonce 和签名再次发送，避免同一签名包被反复用于探测多个动作变种。

当前已落地纯逻辑校验模块 `CommunicationInboundVerifier`，覆盖：

- 缺少 timestamp / nonce / signature。
- 时间戳过期。
- nonce 重放。
- 签名错误。
- 合法签名通过。

外部签名入口不接受任意文本直通。签名通过后还必须解析结构化 JSON，并经过动作白名单：

- `query_status`：只写入状态查询日志和技术负责人摘要，不创建任务、不执行命令、不修改文件。
- `submit_instruction`：把 `text` / `instruction` / `command` 字段里的普通指令转为可追踪任务。
- `approval_decision`：动作名预留，但当前默认拒绝，后续只有审批编号、决策值、风险回流和老板确认链路完整后才能开放。

非 JSON、缺少 `action`、非白名单动作、空指令和外部审批动作都会被拒绝并写入通信日志。

## 后续外部 HTTP 服务准入

真正监听端口前必须满足：

- 默认只绑定 `127.0.0.1`。
- 默认关闭，需要产品级开关显式开启。
- 只允许白名单动作：查询当前产品状态、提交普通指令任务、处理特定审批。
- 每条入站请求都写入通信日志和事件流。
- 任意高风险动作仍必须回到老板决策中心确认。
