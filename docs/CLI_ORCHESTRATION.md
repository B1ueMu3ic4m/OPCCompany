# 命令行编排设计

最后更新：2026-05-07

当前状态：命令行编排已进入单人本地正式使用基线。Codex / Claude Code / Gemini / API 后端均有产品化配置与运行路径；真实终端、作业档案、状态观察、异常恢复和 token 预算边界已接入。本文描述设计原则和维护边界，最新验收记录见 `OPC_COMPANY.md`。

## 目标

OPC Company 把订阅制命令行工具当作可调度员工。产品不抓取浏览器会话，不使用 Cookie，也不伪装网页登录；只启动官方 CLI、记录执行过程、保存作业档案，并把结果纳入 CTO 协调、验收和交付证据链。

## 支持的订阅制 CLI 后端

### Codex

默认角色：

- 技术负责人代理
- 产品架构师
- 审查代理

命令形态：

```bash
codex exec --skip-git-repo-check -m <model> "<prompt>"
```

### Claude Code

默认角色：

- 代码工程师
- 重构工程师
- 测试修复工程师

命令形态：

```bash
claude -p --permission-mode auto --model <model> --effort <effort> "<prompt>"
```

### Gemini CLI

默认角色：

- 界面设计师
- 多模态分析师
- 视觉审查员

命令形态：

```bash
gemini -p --model <model> "<prompt>"
```

## 执行模型

每个任务都会成为一个本地作业：

```text
.opc/jobs/<job-id>/
  brief.md
  cto-plan.md
  agent-task.md
  transcript.log
  artifacts/
  status.json
```

当前运行器需要保持以下链路：

- 创建作业目录。
- 在允许代码修改时创建或选择独立源码执行区。
- 按员工档案和后端配置生成命令。
- 将标准输出和标准错误写入终端大厅。
- 将完整转录写入作业目录。
- 把完成、失败或中断结果转换为公司事件。
- 向技术负责人写入中文摘要。

当前作业档案行为：

- 每次真实点击“运行”都会在当前产品工作目录下创建 `.opc/jobs/<job-id>/`。
- 作业目录包含 `brief.md`、`agent-task.md`、`status.json`、`transcript.log` 和 `artifacts/` 目录。
- `status.json` 会在进程启动前写为运行中，命令结束后更新为完成或失败，并记录退出码。
- `transcript.log` 记录命令行进程返回的标准输出和错误输出。

## Token 预算边界

- 首次运行会包含员工操作档案和本轮任务。
- 同一产品、同一员工、同一后端的 CLI 续会话只发送本轮任务和一行上下文提示，不重复发送完整员工档案。
- 工单 prompt 只保留导入报告中的少量规则、工具和项目文件线索；完整长清单留在导入报告或作业档案。
- 协作消息总线保存短 subject 和有限 body；长报告应写入产物或审计档案。
- 终端大厅默认汇报 + 运行全部会先弹中文确认，避免一次误点消耗多名员工额度。

## Busy / Auth 处理边界

- 正常 busy：有输出、文件变化、测试运行或明确长任务时不打断。
- 异常 busy：长时间无输出、无文件变化、pane 已回到提示符或日志显示 socket/API/session 失败时，先诊断，再结束异常空转任务并拆小任务续跑。
- 授权异常、忙碌、临时异常和等待超时由状态观察器写入中文诊断；不会自动向 CLI 追加未经确认的下一轮输入。
- 作业目录会作为“命令行作业档案：<员工>”进入 `ArtifactRecord` 集合，但**归类为技术维护产物**（`CompanyStore.technicalMaintenanceArtifactTitlePrefixes` 收录 `命令行作业档案：` 前缀）：技术负责人通过维护产物档案中心（`selectedProductRecentMaintenanceArtifacts`）追踪执行证据；老板总控台、产品详情交付区、交付验收中心、运营套件验收抽屉都通过 `selectedProductDeliveryArtifacts` 过滤掉这条记录，不把后台复杂度暴露到老板首页。安全检查点 / 闭环审计报告 / 本地文件索引同样按维护产物归类。

当前隔离体检：

- 检查每个可执行员工是否拥有独立本地员工工作区。
- 检查每个员工工作区是否拥有会话日志。
- 检查每个可执行员工是否拥有运行会话。
- 为代码/测试员工创建稳定的 `.opc/worktrees/<agent>/source` 独立源码执行区。有代码仓库的产品使用独立代码仓库工作区；非代码仓库但能识别为项目根目录的产品使用源码快照隔离；不能安全识别为项目根目录时，只登记隔离目录，不静默切换执行目录。
- 命令行预检和发车计划会区分产品工作目录与真实执行目录。代码/测试员工只有在隔离目录包含真实源码执行区后才会进入该目录运行，否则继续在主工作目录运行并明确提示隔离状态。
- 默认可见预览只展示中文摘要：员工工作区是否已创建、会话日志是否已创建、运行会话状态、代码类员工使用独立执行区还是主工作目录；不展示元数据目录、内部会话日志文件名或独立执行区内部路径。排障所需路径放在折叠的「展开运维详情」里，不进入默认截图和普通复制内容。

运行会话健康巡检：

- CTO/运维后台新增"运行会话健康巡检"按钮（`LocalMaintenanceCenter`），调用 `CompanyStore.runRuntimeSessionHealthAuditForSelectedProduct(staleAfter:)`，默认异常占用阈值 180 秒（最低 60 秒）。
- 巡检覆盖当前产品团队**可执行员工**，逐人核对：运行会话是否存在；会话产品归属是否属于当前产品；状态、能力和后端配置是否匹配当前员工档案；订阅制命令行工具是否能在本机解析；接口模式的接口地址、接口密钥、模型名是否齐全；运行占用是否超过阈值；以及失败次数和最近错误。
- 任一异常（命令缺失、后端漂移、产品漂移、缺会话、异常占用、最近失败）→ `VerificationRecord` 状态为 `.warning`；全部健康 → `.passed`。报告同步写入技术负责人系统消息与事件流。
- **只读不改状态**：不会修改正在运行的员工列表、不会改员工状态、不会写员工协作消息、不会创建作业档案、不会触发模型任务。异常占用只在报告里高亮"提示，本次不恢复"，真正恢复仍由"恢复异常占用员工会话"按钮负责（先巡检诊断、再决定是否恢复，是设计上的两段式）。
- 运行会话创建和复用都会绑定当前产品 ID；产品切换后同一员工的旧产品会话不会被静默复用，异常占用恢复也只处理当前产品或旧快照无产品标记的会话。
- 可见报告不展示底层后端签名、内部状态枚举或错误字段名，只展示中文摘要。
- 异常占用恢复报告必须使用中文状态名和中文字段说明，不直接写 `busy`、`timedOut`、`lastUsedAt` 等内部枚举或字段名。

命令行作业幽灵巡检：

- CTO/运维后台新增"运行命令行作业幽灵巡检"按钮和常驻预览卡片（`LocalMaintenanceCenter`），调用 `CompanyStore.runJobArchiveStaleAuditForSelectedProduct(staleAfter:)`。
- 巡检只扫描当前产品根目录的作业状态文件。作业仍标记运行中、更新时间超过阈值、且对应员工没有真实运行占用时，视为幽灵运行作业。
- 幽灵作业会被写回为已中断，并保留原状态、中断时间和中文中断原因；仍有真实运行占用或未超时的作业只记录在报告里，不会被打断。

终端日志可见摘要：

- 命令行任务、员工聊天和聊天修正只在终端大厅显示工具名、推理强度、执行位置和任务摘要，不回显完整命令数组。
- 默认界面文案使用中文职责词：右侧通信面板显示「智能控制 / 通信」「指令通道」，公司场景显示「OPC 智能公司指挥舱」「本地员工编队」；`AI 控制`、`Agent 编队`、`COMMAND LINK`、`Codex CTO` 这类混排职责词不进入默认可见文案。Codex、Claude Code、Gemini 和模型名仍作为品牌/配置名保留。
- `model_reasoning_effort`、`--skip-git-repo-check`、环境变量名、完整提示词参数、本地会话日志文件名和完整工具路径不得进入默认终端日志；旧日志里已存在的完整路径或旧命令行会在显示层压缩成工具名或隐藏摘要。
- 完整命令仍可保留在命令行作业档案内供运维回查，但老板/CTO 默认界面只看中文摘要。
- 报告写入 `VerificationRecord("命令行作业幽灵巡检")` 和事件流；不写老板聊天、不写员工协作消息、不创建新作业档案、不触发模型任务。
- 可见报告使用「作业 1 / 作业 2」短编号，不直接展示磁盘内部作业编号或状态字段名；真实作业 ID 仍保留在作业档案文件里。

异常占用员工会话恢复：

- CTO/运维后台新增"恢复异常占用员工会话"按钮（位于 `LocalMaintenanceCenter`），调用 `CompanyStore.recoverStaleRuntimeSessionsForSelectedProduct(staleAfter:)`。
- 默认阈值 180 秒（最低 60 秒）。只处理同时满足以下三条的员工运行会话：
  1. 仍在 `runningAgentIDs` 中；
  2. 对应 `AgentRuntimeSession.state == .busy`；
  3. `lastUsedAt` 距今超过阈值。
- 正常 busy 任务（lastUsedAt 较新）不会被打断。
- 恢复时会从 `runningAgentIDs` 移除、把 runtime session 置为 `.timedOut`、失败计数 +1、写入员工终端日志、`appendEvent(.risk)`、写入 `VerificationRecord("异常占用会话恢复")` 和 CTO 报告。
- 不会触发模型任务、不写 `agentMessages` 总线、不写 `.opc/jobs/` 档案；下一次任务仍必须从 OPC 运行入口发起，以保留预检、作业档案和验收链路。

真实终端工作区：

- CTO 后台可以启动当前产品的真实终端工作区，底层会话名按产品稳定生成，但可见报告只显示中文摘要。
- 每个可执行员工获得一个独立终端席位，当前目录使用 OPC 计算出的真实执行目录；代码/测试员工会优先进入独立源码执行区。
- 启动终端席位只写入员工身份、角色和执行目录提示，不自动执行模型任务。
- 任务仍由 OPC 的运行入口发起，以继续保留运行前预检、`.opc/jobs` 作业档案、消息总线、交付证据和验收门禁。
- 启动后 App 会把终端席位状态和终端片段写回员工终端日志，并生成 CTO 报告和验证记录。
- 后台“刷新真实终端日志”会重新捕获每个员工终端席位内容，追加到对应员工终端日志，并写入 CTO 报告和验证记录；如果工作区不存在，则只报告缺口，不启动员工任务。
- 可见预览不展示底层 tmux 路径、会话名、窗口名或 pane 标识，只展示终端工具是否就绪、已连接席位数量和每个员工的执行位置摘要。
- 终端大厅维护区提供「持久终端可用性巡检」：只读检查终端工具是否就绪、真实终端会话是否存在、控制窗口是否连接、员工席位是否齐全；报告写入技术负责人消息、事件和验证记录，不启动模型任务、不创建作业档案、不修改员工状态。

持久 CLI 会话协议：

- Codex / Claude Code / Gemini 先进入统一的「交互协议画像」层：每个画像记录协议形态、会话模式、可识别的会话编号字段、可配置编号格式、就绪信号、本轮结束信号、忙碌信号、授权异常信号、临时异常信号和建议超时。
- 协议形态当前用于分类和后续分支准备；状态观察器仍按统一优先级分类输出。建议超时已接入员工任务运行，Codex / Claude / Gemini 这类长期协议默认获得更长等待窗口。
- 本轮结束信号既可以包含 CLI 自身输出，也可以包含 OPC 写入的任务边界标记；调用状态观察器时应尽量传入本轮新增输出，避免历史终端滚动内容影响判断。
- 运行前预检只展示中文摘要，例如“支持按产品续跑、识别会话编号关键词、监控就绪/忙碌/授权异常/临时异常”；底层提示符、参数、内部字段名和错误片段不进入老板视图。
- 第一版状态观察器已落地：根据画像把输出归类为可继续交互、等待回复、本轮已结束、忙碌中、授权异常或临时异常，并携带识别出的会话编号。它先作为可测试的状态机基础层存在，后续再接入真正的长期输入循环。
- 状态观察器必须区分协议状态信号和异常诊断信号：就绪、本轮结束等协议信号按画像文本识别；授权异常、忙碌和临时异常只在错误前缀、授权失败、额度/忙碌、网络/超时等诊断语境行里识别。单词类异常信号必须按整词匹配，并跳过包含路径或标识符字符的 token，避免路径、文件名、提示词回显或普通说明里的 `timeout`、`network`、`429`、`busy` 被当成真实异常。
- 员工任务结束后，OPC 会观察本轮原始输出并把结果写入运行会话档案，同时在状态变化时向员工终端日志追加中文「OPC 交互状态」摘要。该摘要不展示底层会话编号，不写验收记录，不改变命令退出码、不自动重试、不绕过人工审查。任务是否完成仍以退出码和作业边界为准，状态观察主要用于授权、忙碌、临时异常等诊断。
- 真实终端席位轮询期间也会使用同一套状态观察器，但观察结果只作为诊断输入：捕获到会话编号、就绪提示、忙碌提示或授权异常提示时，系统会保留最近状态供超时摘要和后续档案使用；只有捕获到 OPC 写入的退出标记和退出码，才会认为本轮任务完成。
- 为避免长输出冲掉作业边界，持久终端执行会读取更大的终端历史窗口；回归测试覆盖了超过千行输出后仍能捕获 `__OPC_JOB_EXIT_<id>__` 的场景。
- 状态观察结果当前只驱动一类保守行为：当本轮输出显示授权异常或工具仍在忙碌中时，OPC 会阻止失败后的自动重开，避免在用户未登录或上一轮任务未结束时反复浪费命令行重启。该守门只作用于系统自动异常恢复路径，不阻止老板或技术负责人再次手动运行员工任务；用户重新完成 CLI 登录后，下次手动任务跑通即可让状态从授权异常转为可继续交互。
- 恢复建议以强类型动作加中文标题和中文操作提示保存到运行会话档案。逻辑消费使用枚举，界面只展示中文标题/提示，不展示原始枚举值、底层会话编号或内部字段名。当前动作用于提示、自动重开抑制和受控手动重试入口显隐，不清理会话编号、不写验收记录、不直接启动模型任务。
- 真实终端席位 preflight 与单轮 REPL 发送前的就绪判断已升级为「最近一非空行整行命中专用 prompt」（`CLIInteractionProfile.endsWithReplReadyPrompt`）。tmux scrollback 里残留的旧 `codex>` / `claude>` / `gemini>` 不再把当前还在「正在处理…」的席位误判为可继续交互；旧的 `containsREPLReadySignal` 仅留给观察增量 delta 的状态机使用，避免在 prompt 后还有响应行时误判为未就绪。每次真实终端自动循环开始时都会把「就绪校验：最近一行已确认 \(协议名) 的专用就绪提示」或「就绪校验：未确认最近专用就绪提示，已拒绝自动发送。原因：…」同步写到三处：员工终端日志的 `[OPC 自动循环就绪审计]` 区块、报告 `summaryText`，以及结构化的 `VerificationRecord("真实终端自动循环就绪审计")`（preflight 通过 → 状态「通过」，preflight 拒绝 → 状态「有警告」），技术负责人维护视图可通过 `selectedProductLatestTerminalAutoLoopReadinessAudit` / `selectedProductTerminalAutoLoopReadinessAuditSummary()` 直接读取，`multiAgentArchitectureAuditText()` 末尾也会带上一行中文摘要。该审计正文不含底层参数、`rawValue` / 后端签名 / ANSI；老板总控台和交付验收中心会过滤该维护记录；拒绝路径不消耗循环轮次、不写老板聊天、不写员工协作消息、不创建作业档案。
- 老板总控台、产品详情交付区、交付验收中心和自动化验收抽屉统一读取交付验收过滤列表；真实终端工作区、终端日志刷新、持久终端巡检、命令行链路预检、产品隔离体检、运行会话巡检、异常恢复、历史索引/归档、安全检查点等技术维护记录留在技术负责人维护视图，真实交付证据仍可见。
- prompt 识别在判定前会通过 `CLIInteractionProfile.normalizedForPromptMatching(_:)` 把输出按"行 + 光标"模拟终端：剥离 ESC CSI（颜色、光标控制等无可见副作用的序列）和 OSC（终端 title / 超链接）控制序列；识别 `CSI K` / `ESC[0K` 清光标到行尾、`ESC[1K` 把行首到光标位置改成空格、`ESC[2K` 清整行；CR 只把当前行光标重置到列 0，**不擦掉尾部**，后续可见字符按光标位置逐个覆盖，未覆盖的尾部仍可见；BS 只把光标左移一位，shell 标准擦字 `\b \b` 才会用空格覆盖；其他 C0 控制字节与 DEL 丢弃；中文、`\t` 与 `\n` 保留。带颜色或 OSC title 包装的 prompt 行因此能被正确识别；裸 `processing...\rcodex>` 因为残留 `sing...` 还在显示会被拒绝；只有 `CSI K` / `ESC[2K` 等明确的清行控制符出现，prompt 才算就绪。
- 同一规范化也接入授权异常 / 忙碌 / 临时异常诊断信号判定（`containsAuthenticationIssue` / `containsBusySignal` / `containsTransientIssue`）：真实终端里被 ANSI 颜色或 OSC title 包裹、或经 spinner CR 覆写后写出的 `error: not authenticated` / `warning: rate limit` / `fatal: ... busy` / `error: 429` / `error: network timeout` 仍能命中诊断；但 `isDiagnosticLine` 前缀清单和 `lineContainsAnyDiagnosticSignal` 单词闸（token 必须整词匹配且不能含 `/\-_.` 等路径/标识符标记）保持不变，所以彩色路径 `/var/log/timeout-429-busy.log`、彩色标识符 `NetworkTimeout429BusyProbe`、OSC 包裹的中文提示词回显里出现的 `timeout / network / 429 / busy` 仍不会被误判。该规范化只用于 prompt 与诊断信号的静态识别，不影响轮询期增量解析、`__OPC_JOB_EXIT_<id>__` 退出协议或诊断信号的整词上下文匹配。
- 中文诊断短语识别：`diagnosticPrefixes` 加上中文行首前缀（错误：/ 致命：/ 警告：/ 异常：/ 严重错误：/ 未授权 / 请登录 等）；codex / claude / gemini 三个画像各自补齐中文授权 / 忙碌 / 临时异常短语（如 `未授权` / `请重新登录` / `授权失败` / `服务繁忙` / `已忙碌` / `速率限制` / `请稍后重试` / `过载` / `请求超时` / `连接超时` / `网络异常` / `临时不可用`）。中文短语命中走"substring 命中 + 前后字符不能是 `/\-_.` 路径标记"二段判定（`linePhraseHitAvoidingPathContext`）：中文路径 `/var/log/临时异常.log` / `/etc/codex/未授权.json` / `/opt/codex/服务繁忙-fixture.txt` 不会被误判；普通中文用户提示词回显（不以诊断前缀开头）也不会进入诊断分支。ASCII 单词 / 多词原有匹配规则保持不变，避免英文场景回退。
- 真实终端自动循环停止审计：真实终端路径下循环结束时，如果 stopReason ∈ {授权异常 / 命令行仍在忙碌 / 临时异常 / 等待超时}，会同步写一条 `VerificationRecord("真实终端自动循环停止审计")`（状态「有警告」），并向员工终端日志追加 `[OPC 自动循环停止审计]` 区块；正文使用中文 stopReason.title + operatorHint，不暴露 `rawValue` / 内部 enum / 后端签名。该标题进入 `technicalMaintenanceVerificationTitles`，老板总控台、产品详情交付区、交付验收中心都不展示；技术负责人维护视图通过 `selectedProductLatestTerminalAutoLoopStopAudit` 与维护审计中心读取。注入闭包路径不写入停止审计，避免单测/内部协调器误污染产品级记录。
- 自动输入循环安全门禁、闭包式执行器核心、技术负责人内部协调器和真实终端席位入口已先行落地：创建循环必须有明确任务上下文和 1 到 8 轮的最大轮次；推进循环时只接受 OPC 生成的一行下一步文本。`CLIAutoInteractionLoopExecutor` 在调用发送闭包前复用门禁的 `rejectionReasonBeforeSending` 校验：状态可运行时，如果达到最大轮次、输入来源不是 OPC 生成或文本不安全（空、包含换行），会直接返回拒发，闭包不会被调用；状态已经停止、拒绝或完成时也不会调用闭包。通过校验后才把单行输入交给真实终端轮次或测试注入闭包，由闭包返回 `CLIInteractionObservation` 和超时标记，再交给门禁 `advance` 落账；观察到授权异常、忙碌、临时异常或超时后立即停止并给出中文原因。`CompanyStore` 的内部协调器只允许当前产品团队里的非老板员工参与，缺少技术负责人任务上下文、选中老板或选中非团队员工时直接中文拒绝；维护区真实入口由 OPC 根据任务上下文生成单行下一步文本并发送到当前员工真实终端席位。真实终端路径发送前还会做只读席位预检：缺少终端工作区、缺少员工席位、没有专用就绪提示或非长期协议员工时直接中文拒绝，且不消耗自动循环轮次；就绪路径已通过 fake REPL + tmux 席位验证真实发送、完成信号停止和无老板聊天/无作业档案副作用。真实终端自动循环终端日志使用「OPC 自动交互循环轮次」，人工触发的 REPL 轮次继续使用「OPC 手动交互轮次」，便于技术负责人审计来源。该入口不创建作业档案、不写老板聊天、不在老板总控台暴露入口。
- 续跑失败会记录到当前产品的员工会话档案；同一产品连续失败达到阈值后，OPC 会清理旧会话编号，下一轮从新会话启动，避免过期或被删除的会话反复重试。
- OPC 在真实终端席位中使用 `__OPC_JOB_START_<id>__`、`__OPC_JOB_EXIT_<id>__` 和退出码作为轻量协议标记，确保每次任务都有可追踪边界。
- 向席位发送新任务前会读取最近终端片段；如果发现最近一次开始标记之后没有退出标记，则判定席位仍有未完成任务，拒绝覆盖发送。
- 拒绝覆盖时返回中文失败摘要，并提示先刷新真实终端日志或恢复异常占用会话；这用于区分正常忙碌任务和异常占用。
- 超时时会先向对应席位发送普通中断，短暂等待 OPC 退出 marker；仍未闭合时发送强中断，再等待一次；仍未闭合则关闭未响应的终端席位，下次运行由真实终端工作区重新创建席位。中断事实会写入作业转录、员工终端日志、验证记录和事件流。
- 当前协议已覆盖“协议画像、状态观察结果记录、持久终端轮询诊断、可配置会话编号、一次任务、一次边界、长输出边界保护、续跑失败清理、忙碌守门、超时中断升级、转录归档、安全单行输入、按画像支持 Codex / Claude Code / Gemini 的手动交互轮次（含终端大厅/维护区中文入口）、状态观察驱动的中文恢复建议面板、受控的临时异常单次重试入口、自动输入循环安全门禁状态机、自动输入循环的可注入发送闭包执行器核心、技术负责人内部协调器，以及技术负责人维护区真实终端受控循环入口”。终端大厅员工卡片默认只展示工具、模型、推理强度、执行方式等中文摘要，不直接暴露完整命令数组、`model_reasoning_effort`、`--skip-git-repo-check` 等运行参数；详细命令仅保留在运维详情和 `.opc/jobs/` 作业档案，且测试锁定默认可见文案不再回归到中英文混排。手动交互轮次发送前必须先观察到对应工具的独立行专用就绪提示，避免把输入误发到普通终端；发送后只观察本轮新增输出，并按对应画像里的独立行专用就绪提示（Codex 用 `codex>`、Claude Code 用 `claude>`、Gemini 用 `gemini>`）或本轮结束信号判定本轮完成；非交互型、缺少专用就绪提示或席位未就绪的后端会被中文拒绝，等待超时只报告状态，不自动中断终端席位、不创建作业档案、不启动模型任务。员工恢复建议面板按最近一次状态观察显示中文摘要和应对建议；授权异常和忙碌继续阻止系统自动重开；只有「临时异常」会出现一个明确受控的「手动重试一次」按钮，由技术负责人显式点击触发，触发后只调用一次会话重开，不会进入隐式循环。真实终端受控循环入口仅在终端大厅/技术负责人维护区出现，由技术负责人显式启动，并且每轮输入都必须由 OPC 从任务上下文生成；老板总控台不展示。

本地历史索引与归档：

- 主快照仍是权威状态；`company-history.sqlite3` 只作为可重建查询索引。
- 本地历史索引通过维护巡检或显式重建入口生成，覆盖消息、事件、任务、工作项、审批、产物、验收、记忆、通信日志和员工协作消息；普通保存不做同步全量重建。
- 终端大厅维护区提供「历史索引巡检」，用于手动重建、统计索引内容、写入验收记录并向技术负责人汇报。
- 终端大厅维护区提供「历史归档迁移」，用于把旧消息、旧事件、旧通信日志和旧协作消息复制到归档表；本轮不裁剪主快照、不删除本地文件、不启动模型任务。
- 只有当历史规模、跨产品查询或统计报表需求超过主快照能力时，才考虑从主快照裁剪已归档旧历史，或把更多状态迁移到正式数据库层。

通信网关：

- “生成手机汇报”只生成并排队汇报内容；“发送到就绪通道”才会调用 LOCAL 或 HTTP 调度器。
- 外部通道必须启用、允许汇报、支持出站且配置完整后才会发送；错误信息会隐藏 webhook 路径、查询参数和 token。
- 手机端入站指令必须经过通道启用、指令权限、入站能力和配置就绪守门；外部服务接入时应先使用 HMAC、时间戳和 nonce 校验。
- 外部签名入口还必须使用结构化 JSON 动作白名单；当前只接受 `query_status` 和 `submit_instruction`，外部审批动作保留但默认拒绝。
- 入站指令只创建可追踪任务和通信日志，不直接执行本地命令，也不跳过老板/技术负责人审批。

## 安全规则

- 禁止抓取浏览器订阅会话。
- 破坏性命令必须经过老板批准。
- 改代码的员工必须有明确文件范围。
- 并行实现使用独立源码执行区隔离。
- 技术负责人接收所有员工直接对话摘要。
